# llms.txt и llms-full.txt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Отдавать с `doxynix.space` два статических Markdown-файла — `/llms.txt` (курированный индекс публичных страниц) и `/llms-full.txt` (самодостаточное описание продукта), сгенерированных из кода, а не написанных руками в `public/`.

**Architecture:** Два чистых builder-функции в `src/shared/lib` принимают `baseUrl` параметром (как уже делает `getSitemapUrl`), поэтому тестируются без env. Два route handler'а в корне `src/app` вызывают их с `APP_URL` и объявляют `dynamic = "force-static"`, чтобы ответы стали build-time артефактами. Список публичных страниц выносится в `src/shared/lib/public-routes.ts` и переиспользуется `sitemap.ts` и llms.txt — так тест ловит расхождение между картой сайта и llms.txt.

**Tech Stack:** Bun, Next.js 16.4 App Router (route handlers), TypeScript strict, Vitest, Biome, Oxlint.

**Spec:** этот документ; разделы 1–2 — спецификация (что и почему), разделы 3–5 — план реализации.

## Global Constraints

- Только Bun. `npm` / `yarn` / `pnpm` запрещены. Полный gate перед «готово»: `bun run validate`.
- `apps/web` — единственный workspace с тестами. Юнит-тест запускается как `bun --filter @doxynix/web test <путь>`; скрипт `test` обёрнут в `with-doppler`, поэтому локально нужен залогиненный Doppler CLI (или `CI=true`).
- FSD: `src/shared/**` не может импортировать `app`, `entities`, `features`, `widgets`. Импорт `app → shared` разрешён. `dep-cruiser` (`arch:check`) — жёсткий гейт.
- Biome переписывает литералы: ключи объектов сортируются по алфавиту (`useSortedKeys`), импорты — по группам (`next` → `@doxynix/*` → `@/shared` → относительные). После правок запускать `bun run format` и перечитывать файл.
- Oxlint: `no-console` (только `warn`/`error`/`info`), `typescript/no-non-null-assertion`, `unicorn/filename-case` (kebab-case). В `src/app/**/route.ts` логов не добавляем вообще.
- Комментарии: по умолчанию их нет. Одна строка — только если без неё код читается неверно; максимум две строки, `lineWidth` 100.
- Никаких `TODO` / `TBD` / «заполнить позже» ни в коде, ни в контенте llms.txt.
- Никогда не коммитить с `--no-verify`. Branch: `feat/dxnx-<n>-llms-txt` (номер из Linear), commit: `type(scope): description`, ≤ 72 символов, без тикета в subject; допустимый scope — `web`.
- Не редактировать вручную сгенерированные файлы (`prisma/schema.prisma`, `config.generated.ts`, `packages/shared/src/enums/index.ts`). Задача их не касается.
- `llms.txt` **не** добавляется в `sitemap.xml`: sitemap — для индексируемых HTML-страниц.
- `proxy.ts` не трогаем: `config.matcher` уже исключает `.*\.txt$`, поэтому `/llms.txt` и `/llms-full.txt` не проходят через `next-intl` middleware и rate limiter. Проверено по коду на 2026-11-01.

## 1. Спека: что решили и почему

### 1.1 Что такое llms.txt

Предложение Jeremy Howard (Answer.AI), сентябрь 2024; в августе 2026 — v2. Не стандарт, не RFC. Markdown-файл в корне домена:

- `# Имя` — единственная обязательная строка;
- `> summary` — краткое описание сайта;
- `## Раздел` + список `- [Заголовок](url): одно предложение о том, что там и зачем агенту`;
- `## Optional` — конвенция: то, что агент может пропустить при маленьком контексте.

`llms-full.txt` — тот же домен, но с полным содержимым в одном файле (для больших контекстных окон).

### 1.2 Стоит ли внедрять

Данные 2026 года (см. раздел 5, источники):

| Наблюдение | Значение |
| --- | --- |
| Доля доменов с llms.txt (SE Ranking, ~300k) | 10.13%, не растёт с трафиком |
| Домены с валидным llms.txt, получившие 0 запросов (Ahrefs, 137k) | 97% |
| Кто всё же качает (Ahrefs) | 21.7% SEO-аудиторы, GPTBot 4.5%, ClaudeBot 0.8%, AI-retrieval боты суммарно ~1.1% |
| Цитируемые URL, бывшие `/llms.txt` (ALLMO, 94 614 URL) | 1 (0.001%) |
| Google Search | официально не поддерживает и не планирует |
| OpenAI | GPTBot скачивает файл, использования не подтверждает |
| Anthropic, Perplexity | заявляют, что retrieval читает файл |

Вывод: **не рычаг SEO/GEO.** Ценность — карта для кодинг-агентов (Cursor, Claude Code, Copilot) и дешёвая гигиена: один статический файл, ноль рантайм-стоимости. Риск только один — устаревшие ссылки, и его закрывает тест из Task 2.

### 1.3 Решения для Doxynix

1. Оба файла **генерируются из кода**, а не лежат в `public/`. Причина: `public/llms.txt` выигрывает у route handler'а, если существуют оба, и легко протухает молча.
2. `llms.txt` — только публичные страницы. `/dashboard`, `/auth`, `/welcome`, `/api` не линкуем: это зеркалит `disallow` в `robots.ts` и не помогает агенту.
3. `llms-full.txt` — сжатая база знаний (пайплайн, форматы, лимиты, CLI, MCP, безопасность, FAQ), а не склейка privacy/terms.
4. Язык — английский, один файл в корне. Локализованные `/ru/llms.txt` (v2 разрешает) не делаем: 12 локалей без поддержки превращаются в мусор.
5. MCP-эндпоинт (`/api/mcp`) указываем в обоих файлах: для агентов это полезнее любых маркетинговых текстов.
6. `Content-Type: text/plain; charset=utf-8`, `Cache-Control: public, max-age=3600, s-maxage=86400`. Спека допускает `text/markdown`, но `text/plain` безопаснее для всех клиентов.

Полное содержимое файла после правки (локальный `type RouteConfig` и `const PUBLIC_ROUTES` удаляются):

```ts
// apps/web/src/app/sitemap.ts
import type { MetadataRoute } from "next";

import { APP_URL } from "@/shared/config/env.client";
import { DEFAULT_LOCALE, LOCALES } from "@/shared/config/locales";
import { PUBLIC_ROUTES } from "@/shared/lib/public-routes";
import { getSitemapUrl } from "@/shared/lib/sitemap.utils";

export default function sitemap(): MetadataRoute.Sitemap {
  const sitemapEntries: MetadataRoute.Sitemap = [];

  PUBLIC_ROUTES.forEach(({ changeFrequency, path, priority }) => {
    const languages: Record<string, string> = {};

    LOCALES.forEach((locale) => {
      languages[locale] = getSitemapUrl(APP_URL, path, locale, DEFAULT_LOCALE);
    });

    languages["x-default"] = getSitemapUrl(APP_URL, path, DEFAULT_LOCALE, DEFAULT_LOCALE);

    LOCALES.forEach((locale) => {
      sitemapEntries.push({
        alternates: {
          languages,
        },
        changeFrequency,
        lastModified: new Date(),
        priority,
        url: getSitemapUrl(APP_URL, path, locale, DEFAULT_LOCALE),
      });
    });
  });

  return sitemapEntries;
}
```

    expect(lines[1]).toBe("");

    const urls = collectUrls(buildLlmsTxt(BASE_URL));

    expect(urls.length).toBeGreaterThan(5);

    expect(txt).not.toContain("/auth");
    expect(txt).not.toContain("/welcome");

    expect(txt.endsWith("\n")).toBe(true);
    expect(txt.endsWith("\n\n")).toBe(false);

export function buildLlmsUrl(baseUrl: string, href: string, fragment = ""): string {
  const base = href.startsWith("http")
    ? href
    : getSitemapUrl(baseUrl, href, DEFAULT_LOCALE, DEFAULT_LOCALE);

  if (fragment === "") {
    return base;
  }

  return `${base}${base.endsWith("/") ? "" : "/"}${fragment}`;
}

export function buildLlmsTxt(baseUrl: string): string {
  const sections = LLMS_SECTIONS.map(({ entries, title }) => {
    const lines = entries.map(({ description, fragment, href, title: entryTitle }) => {
      const url = buildLlmsUrl(baseUrl, href, fragment);

      return `- [${entryTitle}](${url}): ${description}`;
    });

    return `## ${title}\n\n${lines.join("\n")}`;
  });

  return `${HEADER}\n\n${sections.join("\n\n")}\n`;
}
