# ZenStack & Prisma Migration Workflow (`apps/web`)

## Overview
`apps/web` uses **ZenStack** layered on top of **Prisma ORM**. The single source of truth for the web database is the ZenStack model definition (`schema.zmodel` or `models/*.zmodel`).

## The Iron Law
```
NEVER EDIT apps/web/prisma/schema.prisma DIRECTLY. IT IS AUTO-GENERATED BY ZENSTACK.
```

---

## Execution Steps

### 1. Modify ZenStack Models
Edit the relevant `.zmodel` file:
- `apps/web/prisma/models/auth.zmodel`
- `apps/web/prisma/models/core.zmodel`
- `apps/web/prisma/models/github.zmodel`
- `apps/web/prisma/models/review.zmodel`
- or root `apps/web/prisma/schema.zmodel`

Declare access control rules directly inside models:
```prisma
model RepoAnalysis {
  id        String   @id @default(uuid(7))
  repoId    String
  status    String   @default("pending")
  createdAt DateTime @default(now())

  // ZenStack access policy:
  @@allow('create,read', auth() != null)
  @@allow('all', auth().role == 'ADMIN')
}
```

### 2. Generate Prisma Artifacts
Execute the ZenStack compiler to produce `schema.prisma` and typed clients:
```bash
bun with-doppler "bun --filter @doxynix/web db:generate"
```
*(This triggers `zenstack-gen.mjs` and `prisma generate --sql`)*.

### 3. Create Migration SQL
Run Prisma migrate dev:
```bash
bun with-doppler "bun --filter @doxynix/web prisma migrate dev --name <descriptive_name>"
```

### 4. Safety Review
Open the generated migration in `apps/web/prisma/migrations/<timestamp>_<name>/migration.sql`:
- Verify no existing data columns are dropped without migration strategies.
- Verify indexes and foreign key constraints.

---

## Verification Checklist
- [ ] Edited only `.zmodel`, never `schema.prisma`.
- [ ] Ran `bun db:generate`.
- [ ] Generated migration has valid SQL and safe constraints.
- [ ] Type check passes: `bun --filter @doxynix/web type-check`.
